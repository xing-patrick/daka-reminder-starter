# 打卡提醒（Daka Reminder）

到点在桌面上浮出一张提醒卡片，点「已完成」立刻消失，平时屏幕上什么都不显示。支持左右滑动查看和安排任意一天的打卡。

- 包名：`com.daka.reminder.starter`（与正式版 `com.daka.reminder` 不同，可以和正式版同时装在一台手机上）
- 适配：Android 8.0（API 26）及以上，小米 HyperOS / MIUI 可直接用
- 体积：无任何第三方 SDK，只有 AndroidX + Material

> 本仓库是 **始发版基线**：打卡 + 实际打卡时间 + 失败置灰 + 任务库/每日清单 + 节假日调休 + 悬浮提醒 + 手表推送。
> 不含后续的时间轴、时段/计时任务、进度条与统计页。

---

## 一、怎么拿到 APK

### 直接下载（推荐）

每次推送到 `main`，构建成功后会覆盖更新同一个 Release，固定直链永远指向最新包：

```
https://github.com/xing-patrick/daka-reminder-starter/releases/latest/download/daka.apk
```

也可以打开 [`releases/latest`](https://github.com/xing-patrick/daka-reminder-starter/releases/latest) 在 Assets 里点 **daka.apk**。不用登录，链接不会过期。

### 自己编译

装好 Android SDK 后执行 `gradle assembleDebug`，产物在 `app/build/outputs/apk/debug/`。

> 这里发的是 **debug 签名的试用包**，不是正式版。debug 签名由构建机器当场生成，每次构建都不同；
> Android 要求同包名同签名才能覆盖安装，所以换一个构建出的包**必须先卸载旧的**，打卡记录会一起清掉。
> 需要能覆盖升级、数据不丢的正式包，用你自己的 keystore 在本地构建 —— 本仓库不提供签名配置，也不发布正式包。

## 二、装到小米手机后必须做的事

**这一步不做，提醒大概率弹不出来。** 打开 App 后右上角菜单 → `权限检查`，会引导你逐项跳转。

| 项目 | 不做的后果 | 在哪开 |
|---|---|---|
| 通知权限 | 完全没有提醒 | 首次启动会自动弹，允许即可 |
| 闹钟和提醒（精确定时） | 提醒延迟几分钟到几十分钟 | 权限检查 → ② |
| **显示在其他应用上层** | **桌面弹不出卡片** | 权限检查 → ③ |
| 电池 → 无限制 | 后台被杀，闹钟不响 | 权限检查 → ④ |
| **自启动 + 后台弹出界面** | **小米专有，不开卡片会被系统拦掉** | 权限检查 → ⑤ |
| 读取日历（可选） | 「法定上班日 / 休息日」规则无法从手机日历同步 | 节假日与调休 → 从日历同步 |
| 穿戴 App 的消息通知 | 手表 / 手环收不到提醒 | 权限检查 → ⑥ 或菜单「手表 / 手环推送」 |

小米的手动路径（HyperOS 可能叫法略有不同）：

- 自启动：设置 → 应用设置 → 授权管理 → 自启动管理 → 找到「打卡提醒」打开
- 省电策略：设置 → 应用设置 → 应用管理 → 打卡提醒 → 省电策略 → **无限制**
- 后台弹出界面：设置 → 应用设置 → 应用管理 → 打卡提醒 → 权限管理 → 找到「后台弹出界面」打开

全部开完后，回到 App 点右上角 → **`预览提醒效果`**，屏幕上应该立刻浮出一张卡片，同时有声音和震动。看到卡片就说明配置成功了。

## 三、两个概念：任务库（模板）和 每日清单（实例）

这是整个 App 的核心，理解了这个就全通了。

### 任务库 = 模板池

存的是「事情本身」，**不绑定任何日期，也不记录完成状态**。任务分两类：

- **重复模板**：带星期规则，比如「每天」「工作日」「周一三五」
- **单日模板**：比如「买牛奶」「牙医 10:00」——**不指定日期**，静静待在库里等你用

### 每日清单 = 某一天的实例集合

主界面滑到的那一天，里面每一条都是**独立的一行数据**（实例）。它们是这么来的：

- **重复模板**：按星期规则自动落进命中的每一天
- **单日模板 / 临时任务**：你在那一天点「从库添加」或「新建」手动加进去

### 一句话记住

> **任务库是模板，日期列表是副本。改副本不动模板，也不动其他日期的副本；
> 改模板 / 删模板则只往下传导到「还没发生」的副本，过去的一律不动。**

所以：

- **想提前安排明天**：向右滑到明天 → 点「从库添加」挑一条，或点「新建」建一个只属于明天的
- **同一件事想出现在好几天**：在任务库建一条模板，然后到每个日期各点一次「从库添加」。加完之后各天互不影响 —— 改今天那条，明天的那条不会变
- **想快速跳到某一天**：点上方中间的日期，弹出月历直接选
- **今天临时不想做**：长按那一条 →「从这天移除」。只影响这一天
- **想彻底删掉一件事**：长按 →「删除模板」。删库里模板的同时，按下面那套规则把「还没发生」的实例一起清掉；**过去、今天已到点 / 已打卡、手动改过的都保留**

### 改 / 删模板会传导到哪些实例

改任务库里的重复模板（名称 / 时间 / 规则），或者**直接删除模板**，走的是同一套单向传导规则：

| 实例 | 改模板 | 删模板 |
|---|---|---|
| 过去的日期 | ❌ 不变，保留历史 | ❌ 保留 |
| 今天已经到点、或已经打过卡的 | ❌ 不变 | ❌ 保留 |
| 今天还没到提醒时间的 | ✅ 跟随 | ✅ 移除 |
| 明天及以后的 | ✅ 跟随 | ✅ 移除 |
| 你手动改过名称/时间的 | ❌ 保留你的改动，之后模板再改也跳过 | ❌ 保留 |
| 从这天移除过的 | ❌ 保持移除 | ❌ 保持移除 |

保存 / 删除后会提示同步了多少条（「已同步 N 条…」/「已同步移除 N 条未来未发生的打卡项」）。**声音和震动开关也走同一套规则**，改模板时一起同步。

> 规则改了导致某些日期不再命中时，那些「自动展开、还没发生、没被手动改过」的实例会被自动撤掉；过去日期不受影响。

**左右滑动**切换日期，范围是当前日期前后各一年。也可以点顶部两侧的 `‹` `›` 一天天挪，点中间日期弹月历，右上角菜单有「回到今天」。

> 过去的日期是**只读**的，只能看完成情况，不能补打卡、不能改。这是刻意的设计，避免误改历史记录。
> 今天和以后都能自由安排。

## 四、批量导入怎么写

任务库界面底部有「批量导入」按钮，导进去的每一条都会变成**任务库模板**，不绑定日期。

对话框上方有六个**快捷示例按钮**（每天 / 工作日 / 周末 / 法定上班 / 休息日 / 单日），点一下就把对应格式的示例追加到输入框，不用记语法。

一行一条，格式是：

```
名称  时间  规则
```

时间和规则都可以省略（省略时间默认 08:00，省略规则默认每天）。

### 规则用关键词明确指定

```
早起 07:00 每天            <- 重复 · 每天
喝水 09:30 工作日          <- 重复 · 周一到周五
游泳 15:00 周末            <- 重复 · 周六周日
阅读 21:00 一三五          <- 重复 · 自定义星期
健身 18:30 周一,周三,周五   <- 重复 · 自定义星期
跑步 20:00 1-5            <- 重复 · 周一到周五
收邮件 09:00 法定上班日     <- 重复 · 跳过法定节假日，调休补班也提醒
大扫除 10:00 休息日        <- 重复 · 周末和法定假都提醒，调休补班不提醒
逛街 14:00 节假日          <- 同上（旧写法继续认，语义已统一为「休息日」）
买牛奶 18:00 单日          <- 单日模板（不指定日期）
牙医 10:00 11月8日         <- 单日模板（写日期也可以，日期不绑定）
早睡 23:00                 <- 不写规则默认每天
冥想                      <- 不写时间默认 08:00、每天
早起,07:00,每天            <- 逗号分隔也可以
```

> **单日模板**在任务库里不绑定任何日期。写「单日 / 单次 / 不重复」或写一个具体日期（如 `11月8日`、`12/20`）都行；日期只用来判定类型，导进去之后需要你在某一天点「从库添加」才会出现。
>
> 规则看不懂的行会被列为**「无法识别」**，不会悄悄变成「每天」。

规则关键词对照：

| 你写 | 解析成 |
|---|---|
| 每天 / 每日 / 天天 | 每天 |
| 工作日 / 平日 / 上班日 | 周一到周五（纯星期，不看节假日） |
| 周末 / 双休 | 周六周日 |
| 一三五、周一三五、周一,周三,周五 | 自定义星期 |
| 周一到周五、一~五、1-5 | 按区间展开 |
| 法定上班日 / 法定工作日 / 调休 / 补班 | 法定上班日（看节假日表） |
| 休息日 / 法定节假日 / 法定假日 / 节假日 / 放假 | 休息日（看节假日表：周末 + 法定假 − 调休补班） |
| 单日 / 单次 / 一次 / 不重复 | 单日模板 |
| 11月8日、12/20 | 单日模板（日期只用于判定类型，不绑定） |

粘贴时输入框下方会实时显示「可导入 N 条模板（重复 X / 单日 Y）」、无法识别的行数，以及前 4 条带类型标签的预览，确认没问题再点导入。

导入时会自动跳过重复项（同名 + 同时间 + 同类型 + 同规则视为重复）。导入出来的模板默认「声音 + 震动都开」，需要静音的导入后到任务库里单独关。

## 五、日常操作

**主界面**（底部三个按钮）

- **从库添加**：打开任务库列表，挑一条模板加进当前这一天。同一模板可以加到多个日期，各天互不影响
- **新建**：建一个只属于当前这一天的临时任务，不进任务库
- **任务库**：管理所有模板

**列表操作**

- **打卡**：点任意一行，圆圈打勾、文字变灰划线（只有今天能打，其他日期只读）
- **长按一行**：
  - **编辑这一条** → 只改当前这一天的这条（名称、时间、声音/震动），模板和其他日期都不变
  - **从这天移除** → 只从这一天拿掉；重复模板不会在下次打开时把它补回来
  - **删除模板** → 只有来自任务库的才有这一项。删库里模板的同时，按第三节的规则移除「今天还没到点 + 以后」且没被手动改过的实例；过去和已发生的保留

**任务库**

- 分三组：「常规重复（每天 / 工作日 / 周末 / 自定义）」「法定上班日 / 休息日」「单日模板」，每组的条目都带规则标签
- 点一条 → 编辑模板（改名称、时间、类型、排期规则、声音/震动）
- 长按一条 → 编辑 / 删除
- 底部「批量导入」→ 一次性建一批模板，对话框里有六个类型示例可直接插入

**右上角菜单**

- 回到今天
- 节假日与调休
- 闹钟式持续提醒（开关，默认开）
- 提醒铃声
- 手表 / 手环推送
- 预览提醒效果 / 权限检查 / 清空全部

**提醒弹窗**

- **已完成** → 记录打卡、卡片和通知立即消失、停止响铃、自动排下一次
- **稍后 10 分钟** → 停止响铃，10 分钟后再弹一次；**最多 3 次**
- **放弃本次**（卡片底部小字）→ 直接判定失败。**要点两次**：第一次只是把文字变成「再点一次确认放弃」，4 秒内再点才生效，防止误触

默认开启「闹钟式持续提醒」：**不点上面任何一个按钮，声音和震动就会一直循环**，卡片也不会自己收起。关掉开关后回到「响一轮 + 15 分钟自动收起」。声音震动都关的任务不进持续模式。

> 以前这里有个「静音（留着卡片）」按钮，现在去掉了：它只是停声音、卡片继续挂着，等于把「没处理完」的状态藏起来。真要结束，要么打卡，要么明确放弃。

### 时间记的是「实际打卡那一刻」

不管从哪儿打卡，都会记下**你按下去的真实时间**，列表里的时间随即变成这个时间：

| 情况 | 计划 | 实际 | 列表显示 |
|---|---|---|---|
| 延后打卡 | 08:00 | 08:37 | **08:37**，副标题标「原定 08:00」 |
| 提前打卡 | 07:30 | 06:50 | **06:50**，副标题标「原定 07:30」 |
| 准点打卡 | 10:00 | 10:00 | 10:00，不标原定 |

两个入口走的是同一个方法，所以记下来的时间完全一致：**悬浮卡片上的「已完成」**、**在 App 列表里点一行**。
取消打卡（再点一次）会回到原定时间，并且重新参与当天的排期。

> 排序仍按**原定时间**排。打卡后条目留在原位、不会跳到别处，避免点完就找不到它。

### 延迟 3 次还没完成 = 本次打卡失败

「稍后 10 分钟」不是无限的：

| 已延迟次数 | 左边按钮 | 底部小字 | 点下去 |
|---|---|---|---|
| 0 ~ 2 | 稍后 10 分钟 | 放弃本次 | 左键 = 延迟；小字 = 放弃（要确认两次） |
| 3 | **放弃本次** | 隐藏 | 点一下（同样要确认两次）= 立即判定失败 |

延迟满 3 次之后的那一轮提醒，是这条任务当天最后一次机会：

- 点「已完成」→ 正常打卡，记实际时间
- 点「放弃本次」→ 立刻失败
- **10 分钟内什么都不做 → 自动判定失败**（不需要你操作）

> 不想等了也可以随时主动放弃 —— 底部那行小字一直都在，不用等到第 3 次。放弃和「延迟用尽」的下场完全一样。

判定失败之后：

- 不再有任何提醒（当天的闹钟、稍后延迟、通知、重复通知全部撤掉）
- 列表里这条变成**灰色 ×**，副标题写「打卡失败」
- 还能点一下**手动补上**：补上就按当时的实际时间记录，`failed` 标记清掉

> 「失败」只是「系统不再叫你了」，不是「不许打卡」。补上之后当天统计里算完成。

## 六、节假日与调休

菜单 → **节假日与调休**。这张表只影响两条规则：**法定上班日** 和 **休息日**。

| 规则 | 命中条件 |
|---|---|
| 法定上班日 | 周一至周五 − 表里标「放假」的日子 + 表里标「补班」的周末 |
| 休息日 | 周末 + 表里标「放假」的日子 − 表里标「补班」的周末 |
| 工作日 / 周末 / 每天 / 自定义 | 纯按星期，**不看这张表** |

两条法定规则严格**互补**：任何一天要么是「法定上班日」，要么是「休息日」，不会两边都命中，也不会两边都不命中。所以「只在休息日做的事」只用建一条「休息日」模板，不必再拆成周末 + 法定假两条。

优先级：**调休补班 > 法定放假 > 按星期推**。没有导入任何节假日数据时，两条规则都退回纯按星期判断（周一到周五上班、周六周日休息），行为完全正常。

### 数据怎么来

1. **从日历同步**：点「从日历同步」会申请读取日历权限，然后找手机里名字含「节假日 / 假期 / 放假 / 法定 / holiday」的日历（小米、华为都有这类订阅日历），读它的全天事件：
   - 标题含「班 / 补班 / 上班」→ 判为**调休补班**
   - 其余 → 判为**法定放假**
   - 多天假期会铺成一段日期
2. **手动导入**（读不到时的兜底）：一行一条，日期后面写「休」或「班」

```
10月1日 休
10月1日-10月7日 休
10月11日 班
2026-12-25 放假
2026/9/27 补班
10/1~10/7 休
```

不写「班」默认按放假。日期支持 `10月1日` / `2026-10-01` / `10/1`，区间支持 `-` `~` `至` `到`。不写年份用今年；如果这天已经过去半年以上，自动算到明年。

> 各家 ROM 的节假日日历命名不统一，且有的需要你在系统日历里先订阅「节假日」日历。读不到就用手动导入，最可控。
> 改完表之后，未来各天的实例会按新规则重新展开、重新排闹钟；过去日期不动。

## 七、提醒与手表

### 每个任务单独设置声音和震动

任务库编辑、当天任务编辑（含新建）里都有两个开关：

| 开关 | 关掉之后 |
|---|---|
| 声音 | 到点不响铃，震动和卡片照旧 |
| 震动 | 到点不震，声音和卡片照旧 |

两个都关 = 到点只弹卡片，完全静音。新建任务默认两个都开；老版本升级上来的任务也按「都开」处理，不会突然变静音。

列表里能直接看出来：声音关了显示「· 静音」，只关震动显示「· 无震动」；悬浮卡片上也会写「只弹卡片 / 不响铃 / 不震动」。

### 声音跟着系统静音走，震动不跟

声音走**通知音量**（`USAGE_NOTIFICATION`），不再像闹钟那样穿透静音：

- 手机静音或仅振动 → **不出声，但照旧震动**（只要这条任务的「震动」开着）
- 开着勿扰模式 → 不出声，同样照旧震动
- 正常模式 → 按系统通知音量播放

> 这是刻意分开的：静音是「别吵到别人」，震动是「别让我漏掉」。想看清单又不想被震，去任务里把「震动」单独关掉。
>
> 如果你在静音时连震动都没感觉到，先确认三处：① 这条任务的「震动」开关（列表里会显示「· 无震动」）；② 小米「设置 → 声音与振动」里有没有关掉整体振动；③ 手机没开「勿扰 → 完全静默」。
>
> 睡前把手机调静音就不会被打卡提醒吵醒。需要绝对叫醒的场合请用系统闹钟。
> 手表上的声音和震动由手表自己的设置控制，不受这里的开关影响。

### 换一个专属铃声

默认用系统通知音，会和微信、QQ 的通知音混在一起，不容易分辨。菜单 → **提醒铃声**：

| 选项 | 说明 |
|---|---|
| 从通知音里选… | 调起系统铃声选择器，只列通知音 |
| 从闹钟铃里选… | 同上，列闹钟铃声 |
| 从来电铃声里选… | 同上，列来电铃声 |
| 恢复系统默认通知音 | 回到系统默认 |
| 静音（不出声） | 声音关掉，震动照旧 |

前三项会打开安卓自带的铃声选择界面，**能试听**，部分 ROM 还能挑本地音频文件。选完点菜单「预览提醒效果」立刻验证。

铃声是**全局一个**，所有开着「声音」的任务共用。

> 换铃声只改「响什么」，不改「什么时候响」——声音仍然走通知音量，手机静音或勿扰时照样不会响。
> 如果选的本地文件后来被删掉、权限被收回，会自动退回系统默认通知音，不会变成完全没声音。

### 持续提醒

默认开启「闹钟式持续提醒」：没点任何按钮时，声音和震动会一直循环，卡片也不自动收起。

- 点「已完成」→ 打卡 + 停响 + 卡片消失
- 点「稍后 10 分钟」→ 停响 + 10 分钟后再来
- 点「放弃本次」→ 停响 + 判定失败（要确认两次）
- 声音震动都关的任务不进持续模式，卡片 15 分钟后自动收起

没有悬浮窗权限时卡片出不来，声音照样按设置循环。此时通知是唯一入口：点通知打开 App，在今日列表里点一下那一行就能收尾。
菜单里可以关掉这个开关，回到「响一轮、15 分钟后卡片自动收起」。

### 息屏时也要能响

这里有个坑，值得写清楚：

`AlarmManager` 触发广播时，系统只借给 App **大约 10 秒**的唤醒时间。`onReceive` 一返回这笔时间就收走，屏幕又是熄的，CPU 立刻进入睡眠。而弹卡片、启动播放器、调震动都排在 `Handler.post` 里 —— 一旦 CPU 睡着了，这些代码**根本没机会执行**。

表现就是：手表收到通知了、通知栏也有那条记录，但手机一声不响也不震。因为通知是**同步**发的，声音和震动在 post 回调里，差了一个"CPU 还醒着"的条件。

所以 `ReminderPresenter.show()` 一进来就先拿一个 `PARTIAL_WAKE_LOCK`（`util/KeepAwake.kt`，带 30 分钟超时兜底），`AlertFeedback` 里的 `MediaPlayer` 也设了 `setWakeMode`，两层一起保证：

- 广播返回后 CPU 不睡 → post 能跑完 → 卡片弹出来、播放器启动、震动开始
- 一旦启动，声音由系统的 `AudioFlinger` 执行、震动由 `VibratorManagerService` 执行，都在 App 进程之外，之后即使本进程被冻结也不会断

点「已完成 / 稍后」时释放锁。`WAKE_LOCK` 权限在 Manifest 里已声明。

> 如果遇到"息屏还是没反应"，先看点亮屏幕后**有没有那张卡片和通知**：有 → 是本进程没活下来（下一步要加前台服务）；完全没有 → 是闹钟本身没到，去查精确闹钟权限、自启动、省电策略。

### 为什么曾经「有声音、没震动」

这是 Android 13 之后 OEM 一条很容易踩的隐藏规则，不是普通 bug：

从 SDK 33 起，**三星 One UI、小米 HyperOS 等系统会丢弃来自后台进程、且没有显式声明用途的振动请求**。老的写法 `vibrator.vibrate(effect)` 默认用途是 `USAGE_UNKNOWN`，而提醒是在广播（后台）里触发的 —— 于是声音正常响，触感被系统直接扔掉，也不报错。

修法是调用 `vibrate(effect, VibrationAttributes)` 并显式声明 `USAGE_ALARM`。现在 `AlertFeedback.startVibration()` 就是这么做的（SDK 33+ 走新接口，更老的系统走老接口）。

另一处也一起修了：声音播完时只释放播放器，不再顺手把震动 `cancel()` 掉 —— 短提示音播完会连带切断震动，表现同样是「有声无震」。

**怎么自己确认**：菜单 →「预览提醒效果」，除了弹出卡片，还会用 toast 显示这次的实际结果：

| 显示 | 含义 |
|---|---|
| `声音✓ · 震动✓` | 两个都起来了 |
| `声音✓ · 震动失败：xxx` | 被系统拒了，xxx 是原因 |
| `声音关 · 震动关` | 这条任务自己把开关关了（列表里也会标「· 静音 / · 无震动」） |
| `静音/勿扰不出声` | 手机当前是静音或勿扰，声音按设计不出 |

### 华为手表 / 手环

**先说结论：桌面悬浮卡片不会同步到手表，系统通知是手表唯一的通路。** 悬浮卡片是 App 自己画在手机屏幕上的窗口，只存在手机；华为手表靠「华为运动健康」把**手机的系统通知**镜像到表上。所以只要还想让手表收到提醒，通知就必须保留 —— 去掉通知 = 手表完全收不到，而声音和震动是独立的，照常响。

配置：

1. 手机装好「华为运动健康」并和手表配对
2. 运动健康 App → 设备 → 消息通知 → 打开「打卡提醒」（菜单 → 手表 / 手环推送 → 打开穿戴 App 设置，可一键跳过去）
3. 手表上会显示提醒标题和正文

#### 手表上只能看，不能操作

这不是代码写错，是穿戴设备的限制：华为手表走的是「华为运动健康」的**通知镜像**，只保留标题 + 正文，通知上的自定义按钮会被剥掉，所以表上看不到「已完成」。更关键的是，**在表上点通知也只在表上查看 / 收起，动作不会回传给手机**。指望「点一下表就把卡打上」不成立，实测也确认了这一点。

所以这一版把通知退化成**纯展示**：

- 通知里不再挂「已完成 / 放弃本次」按钮 —— 表上显示不出来，手机上又有悬浮卡片，留着只是多一条入口
- 点手机上的那条通知只做一件事：打开 App 首页，**不会改动任何打卡状态**
- 打卡、稍后、放弃全部在悬浮卡片上完成

一句话：**手机负责交互，手表负责提醒**。表震一下、看一眼任务名和时间就够了。

同一个对话框里还有：

- **发送通知**（默认开）：想让手表收到就保持开；彻底不用手表了可以关掉，通知栏就不再留那条重复记录，声音震动照旧
- **重复提醒**（默认开）：见下面「手表震得太短」
- **推送增强**：收得慢 / 收不到时打开，把通知提到 `IMPORTANCE_HIGH`，穿戴设备更容易同步
- **发一条测试通知到手表**：现场验证桥接通没通

#### 手表震得太短 / 只震一下

**单条通知能让手表震多久，是手表固件和「华为运动健康」决定的，App 改不了。** 通知里没有「震动时长」这个字段，所以任何 App 都做不到「让手表连续震 10 秒」—— 连系统电话通知也不行。

App 唯一能控制的只有「发几次」。所以「重复提醒」这个开关做的事是：提醒一直没被处理时，**每 20 秒重发一次通知**，手表每收到一条就震一轮 —— 用次数换时长。最多持续 30 分钟，点「已完成 / 稍后 / 放弃本次」立刻停。

前提是「闹钟式持续提醒」开着（关了就只提醒一次）；关掉「重复提醒」则恢复成只震一轮。

> 手表的振动强度、静音规则、勿扰时段也要看表侧设置：运动健康 App → 设备 → 通知 / 振动，以及手表自己有没有开「勿扰」。

> 这里没有集成 Wear OS 官方 SDK。华为手表、小米手环这些都不走 Wear OS Data Layer，通知桥接是唯一通用通路，也省掉了额外的 Google Play 服务依赖。

**数据模型**（v3）：

- `TaskTemplate` 任务库模板。不绑定日期、不带完成状态。`REPEAT` 带 `ScheduleMode` 排期规则，`ONCE` 不指定日期
- `DayTask` 某一天里的一条实例。从模板复制出来后独立；`templateId` 为空表示当天临时任务；`removed` 是墓碑，防止模板把已移除项补回来；`customized` 表示手动改过，之后模板同步会跳过；`auto` 表示这条是按规则自动展开的，规则变化时才可能被撤掉（手动「从库添加」的不会被撤）；`sound` / `vibrate` 是这条任务到点要不要出声、要不要震动；`doneAt` 是实际打卡时刻（`-1` = 未打卡），`timeText` 优先用它；`snoozeCount` 是已延迟次数，`failed` 是延迟用尽被判定失败
- 存储在 `daka_store_v3`：`templates` 一份 + `days` 按 epochDay 索引若干份 + `holidays` / `workdays` 两张日期集合

打开某一天时，`entriesFor()` 把命中的重复模板展开成当天实例并落盘；之后所有增删改打卡都只作用于那一份列表，**不回写模板，也不碰其他日期**。改模板由 `syncTemplate()`、删模板由 `deleteTemplateWithSync()` 按同一套规则单向传导到未发生的实例。

设计上的取舍：

- **不用 Room / DataStore**，只靠 SharedPreferences 存 JSON，减少依赖 = 减少云编译失败概率
- **不用 App Widget**，因为你要的是「平时不显示」，Widget 做不到按需出现
- **不用前台服务**，靠 BroadcastReceiver 直接 addView。窗口可见会提升进程优先级，实测足够
- **不用 setFullScreenIntent**，避免 Android 14 对全屏通知的严格限制
- **模板与实例分离**，这样「改某一天不影响其他日期」是天然成立的；模板传导是额外加的单向规则
- **闹钟按实例 id 排期**，所以改某天某条的时间只会重排那一条
- **声音用通知音量而不是闹钟音量**，宁可少打扰也不穿透静音；需要强制叫醒的场合用系统闹钟
- **通知渠道保持无声**，声音和震动只由 App 按任务开关播放，避免渠道一声 + App 一声双重响，也才能真正按任务关掉
- **不集成 Wear OS SDK**，手表走系统通知桥接，一套代码同时覆盖华为表、小米手环，且不引入 Google Play 服务依赖
- **节假日数据不硬编码**，优先读手机日历，读不到用手动导入，避免内置年度表过期
- **打卡时间只存不覆盖**：`doneAt` 单独一个字段，不去改 `minuteOfDay`。这样取消打卡能干净地回到原定时间，模板同步的「还没到点」判断也不会因为打了卡而失真
- **失败只是「不再提醒」**，不是禁止打卡。仍然允许手动补上，避免一次开会错过就把当天的记录永久锁死

## 九、常见问题

**Q：App 需要一直挂在后台吗？**

不需要。提醒走的是系统 `AlarmManager`，即使 App 进程被完全杀掉、手机重启过，到点系统也会把 App 唤醒一下去弹卡片。小米的「自启动」权限不是让它一直在后台跑，而是允许系统到点时把它拉起来。

**Q：没有声音或震动？**

先看这条任务自己的开关。在任务库里编辑它、或在当天列表里长按「编辑这一条」，底部有「声音」「震动」两个开关；两个都关就只会弹卡片。

再看手机状态：声音走**通知音量**，手机设为静音或开了勿扰时，按设计就是不出声（只震动）。把手机调回正常模式，点菜单「预览提醒效果」就能当面验证。

- 铃声可能被选成了「静音」，菜单 →「提醒铃声」看一眼当前值
- 声音大小跟系统“通知音量”一致，不是闹钟音量
- 震动只看任务的「震动」开关
- 想关掉循环，菜单 →「闹钟式持续提醒」把勾去掉

**Q：提醒一直响会不会很烦？**

所以现在可以按任务关：不重要的任务把「声音」关掉只留震动，或者两个都关只弹卡片。整体嫌吵就在菜单里关掉「闹钟式持续提醒」。手机静音或勿扰时，声音本来就不会响了。

**Q：华为手表怎么收提醒？**

菜单 →「手表 / 手环推送」→ 打开穿戴 App → 在「华为运动健康」里开启本应用的消息通知。手表靠镜像这条系统通知来收提醒（桌面悬浮卡片不会过去），所以「发送通知」别关。手表上只能看、不能操作：按钮显示不出来，点表上的通知也不会回传手机，打卡还是在手机上的悬浮卡片完成。收不到就开「推送增强」，再点「发一条测试通知到手表」验证。详见第七节。

**Q：节假日读不到怎么办？**

各家 ROM 的节假日日历命名不统一，有的还得先在系统日历里订阅「节假日」日历。读不到就点「手动导入」自己粘一份，格式见第六节。手动和同步来的数据会合并，不会互相覆盖。

**Q：翻到明天，为什么有些任务没出现？**

重复模板按星期规则自动出现；单日模板不指定日期，不会自己出现。想让某事出现在明天：滑到明天 →「从库添加」挑它，或「新建」一条只属于明天的。

**Q：明天的提醒排上了吗？**

排上了。每次打卡、编辑、打开 App 都会重排今天到未来 8 天的所有实例。所以你在今天安排好明天的事，明天的提醒就已经在队列里了。

**Q：我改了今天这条的名字，明天同名的会跟着变吗？**

不会。每一天里的每一条都是独立数据，改哪条只影响哪条。要改「源头」得去任务库改模板；模板改动会传导到「今天还没到点 + 以后」那些没被你手动改过的实例（过去、今天已到点、已打卡的不动），详见第三节。

**Q：我把今天这条移除了，明天还会出现吗？**

明天照常出现。移除只作用于这一天，而且留了墓碑，重复模板不会在下次打开今天时把它补回来。

**Q：我从任务库删了模板，各天已经加好的会没吗？**

分情况。删模板和改模板走同一套规则：**今天还没到点、以及以后那些日期里，没被手动改过、没打卡、没移除的实例会跟着一起删掉**；过去的、今天已经到点或已打卡的、你手动改过名称/时间的，都原样保留。删除时会提示同步移除了几条，详见第三节。

**Q：能回到昨天补打卡吗？**

不能，过去的日期是只读的。这是刻意设计，避免误改历史记录。

**Q：想改包名 / 应用名？**

应用名改 `app/src/main/res/values/strings.xml` 里的 `app_name`，改完和应用图标一起看效果即可，不需要动代码。

包名（装到手机上的身份）就是 `app/build.gradle.kts` 里的 `applicationId` 一行，改它就够了。
`namespace` 和 Kotlin 的 `package` 声明是代码内部的命名空间，跟装机身份无关，不必跟着改 —— 本仓库就是把
`namespace` 保持为 `com.daka.reminder`、只把 `applicationId` 改成 `.starter`，所以两个版本能共存。
